## Performance

We've optimized Vite server startup time and static data generation.

---

Let's compare the performance before and after the updates using the developer documentation you're currently viewing.

| Metric                                   | Before      | After         |
| ---------------------------------------- | ----------- | ------------- |
| **Vite Server Startup Time**             | `10s ~ 15s` | _`0.3s ~ 5s`_ |
| **Initial Resource Compilation/Loading** | `15s ~ 20s` | _`1s ~ 4s`_   |

<Box>
  *Cold starts still take longer than we'd like, but subsequent runs, such as
  restarting the server, have improved significantly.*
</Box>

## Island

The `\<Island />` component has been added.

The application root no longer loads and executes an Island's children immediately. Instead, it renders them when the specified hydration condition is met.

```tsx
import { Island } from "sendary/components";
import Comments from "../components/Comments";

export default function PostPage() {
  return (
    <article>
      <h1>Static article content</h1>
      <p>This content is ready without waiting for the comments UI.</p>

      <Island hydrate="visible">
        <Comments />
      </Island>
    </article>
  );
}
```

<Box>
  For more details, see the [`
  <Island />` documentation](/docs/island).
</Box>

## HMR Improvements

HMR now covers not only the `/pages/` directory but also the dependencies of modules within `/pages/`.

## Other Improvements

There are also various optimizations and minor updates.

### Development Mode

- **Switched page compilation from sequential processing to batch compilation**

  Multiple pages are now processed together, reducing the waiting time that previously increased as the number of pages grew.

- **Applied batch compilation to recompilation on file changes**

  Pages are now recompiled just as efficiently when you modify them during development.

- **Parallelized initial page loading**

  Layouts, error pages, actual page modules, and data requests are now loaded concurrently instead of waiting for each one to finish in sequence.

- **Improved initial resource compilation and loading**

  Resources required for the initial page load are now prepared in parallel, reducing prolonged loading states.

- **Removed unnecessary full-page reloads caused by `.sendary/index.html`**

  Internal files generated by Sendary are now excluded from Vite's file watcher, eliminating the `page reload .sendary/index.html` log and the unnecessary full-page reload that occurred when starting the dev server.

### Production Mode

- **Recompile only server modules immediately before static HTML generation**

  Previously, Sendary rebuilt each page's browser bundle even though client bundles were not needed for SSR.

- **Preload the current page's static props JSON in each generated HTML file**

  Data requests can now start as soon as the HTML is parsed, rather than waiting for JavaScript to execute. This reduces the network waterfall during initial hydration.
